# PRD：投研深度分析链路重构（把「两跳 LLM」合并为「一跳 + 证据包」）

状态：**已拍板，进入实施（2026-09-02）**
关联文件：[TECH_DESIGN.md](./TECH_DESIGN.md) · [TASK_LIST.md](./TASK_LIST.md)

## 1. 问题陈述

### 1.1 用户原话

> 「这AI返回的答案有点太小白了。。。咱们的Agent最好别在回答问题的能力上比GPT 5.5或者5.6逊色特别多，不然让人觉得没太大使用意义」「会有点傻吗这个」

> 「联网有一个问题就是会慢一点」「现在这个AI如果不联网跟智障一样」「联网打开了它返回的答案还是很水」「Claude opus太慢了」

复现场景：用户问「黄金和比特币近期行情大变动的原因」，AI 回答是「地缘局势升温、市场流动性趋紧」这类无点位、无数据、无事件的纯套话。

### 1.2 为什么「水」——四条独立成因，代码级定位

**成因 A：投研工具根本不喂数据给模型。**
`app/services/investment_expert_client.py:93-99`：`ask_investment_expert` 从头到尾只拿到用户那句话（`messages=(LLMMessage(role="user", content=message),)`），`tools=()` 意味着它也不能自己去取数据。它唯一的信息源是训练记忆。模型编套话不是模型能力不足，是没给它任何可引用的事实。

**成因 B：证据在回灌给主脑的路上被截成了半句。**
`app/agents/runner.py:57-59` 的 `_summarize()` 把所有工具结果统一硬切 500 字符，且是从 JSON 中间硬切、结尾是破损的转义串。PR #60 刚把 Tavily 结果做到 5 条 × 每条 500 字（2500~3000 字），模型实际只看得到前 500 个字符，而且不知道自己被截断了。**联网确实搜到了，但搜到的东西 80% 没送达模型**——这条是 planner 读代码时发现的，brief 里没提到，且单独修复就能见效，与后续改动解耦。

**成因 C：系统提示词硬性禁止深度回答。**
`app/container.py:105-114` `_OUTPUT_STYLE_GUIDE` 要求「篇幅严格控制在 200~300 字以内」「杜绝长篇大论与过度分析」。一个包含四个资产、每个都要给点位+涨跌幅+导火索+资金证据的归因分析，物理上装不进 300 字。模型在「给具体数据」和「守字数」之间只能选后者——套话是当前提示词的正确答案。

**成因 D：投研子模型自己也被限死在 150-200 字。**
`_EXPERT_SYSTEM_PROMPT`（`investment_expert_client.py:18-21`）要求「150~200 字以内」。链路变成：无数据输入 → 150字套话输出 → 被 `_summarize` 截断 → 主脑再压成 300 字。每一层都在做有损压缩，且压缩的都是本来就没有的信息。

### 1.3 为什么「慢」

当前是三轮 LLM 串联：主脑判断调工具（顶级模型，3-8s）→ `ask_investment_expert` 内部独立分析（`AGENT_INVESTMENT_EXPERT_LLM_MODEL`，2-15s）→ 主脑读结果生成最终回复（顶级模型，5-10s）。

**与 brief 转述不符的事实**：中间那个「快速小模型」在实际部署里并不便宜也不一定快。`.github/workflows/deploy-staging.yml:74` 默认值是 `deepseek-v4-flash-max`，而 `.env.example:107` 自己的注释写着「比 opus-low 贵，别当便宜档用」；`.env.example:112` 示例值直接是 `AGENT_INVESTMENT_EXPERT_LLM_MODEL=gpt-5.6-terra`——跟主脑同一个模型。现状很可能已经是「两轮顶级模型串联」，「1-2秒快速档」只存在于配置注释的设计意图里，没有在实际配置中兑现。

结论：中间这一跳付出了完整的延迟成本，换回来的是 150 字无数据套话——负收益。

## 2. 目标

1. **有据可查**：深度分析类问题的回答中，至少包含 3 项来自本轮实际抓取的具体数据（点位/24h涨跌幅/资金费率/持仓量/具体事件与时间），且不出现套话负面清单里的句子。
2. **不变慢**：端到端中位数 20~35 秒（与现状 10~33s 基本持平）。砍掉一整轮 LLM 调用的收益，抵消输出变长带来的额外 token 时间。
3. **深浅分层**：简单查询（余额/持仓/单一价格）保持 200~300 字；深度分析放宽到 500~800 字，且分层判断不依赖模型的主观话题分类（见 TECH_DESIGN §4.8）。
4. **零回归**：PR #61 的路由边界、PR #60 的联网搜索链路、PERSONA_LOCK、交易草案安全规则，全部逐条守住。

## 3. 非目标（本次明确排除）

- **temperature 调优**：`LLMProvider.complete()` 协议（`app/agents/llm.py:55-58`）无此参数，本次不扩协议，只靠提示词结构压套话。
- **PERSONA_LOCK / 模型身份识别**：`app/container.py:75-89` 一字不动。
- **交易草案安全规则**：`_TOOL_GUIDE` 里除【投研深度分析】两句外的所有段落、`_TRADING_RULES` 全段，一字不动。
- **PR #61 的路由排除逻辑**：`runner.py` 76-111 行、316-331 行，本次 diff 必须为 0 改动。
- **新增行情数据源**：不接第三方黄金/美股行情，Core Ticker 覆盖不到的标的按「仅新闻定性」降级（见遗留问题 ①）。
- **工具改名**：`ask_investment_expert` 名字保留（见遗留问题 ④）。
- **超时数值**：`llm_timeout_seconds` / `llm_max_output_tokens` / `core_timeout_seconds` / `tavily_timeout_seconds` 均不动。

## 4. 延迟预算（用户最关心的问题：会不会等很久）

| 阶段 | 现状 | 改后 |
|---|---|---|
| 主脑第 1 轮（选工具） | 3~8s | 3~8s |
| 中间跳 | expert LLM 2~15s | 证据抓取并行执行，软超时 6s → 1~2s |
| 主脑第 2 轮（生成回复） | 200~300字 ≈ 5~10s | 500~800字 ≈ 13~24s |
| **合计** | **10~33s** | **17~34s** |

净效果：砍掉一整轮 LLM（−2~15s）换来更长输出（+8~14s），中位数基本持平。最坏情况仍由既有的 `llm_timeout_seconds=120` + `llm_max_output_tokens=4096`（最坏 80~100s）兜住，不需要新增熔断。详见 TECH_DESIGN.md §7。

## 5. 遗留问题拍板结果（2026-09-02，产品方确认，全部采纳）

**① 黄金等非加密标的数据缺口 —— 接受当前设定。**
BTC/ETH 等加密标的给真实点位/涨跌幅/资金费率；黄金等非加密标的基于实时新闻给出宏观动因与传导逻辑，**不编造虚假盘面点位**。本次不接入第三方黄金/大宗商品行情源，维持范围。

**② Redis 10分钟缓存 —— 直接下线。**
避免用旧价格做点位归因，理由见 TECH_DESIGN §4.3。

**③ Core 行情软超时 —— 定 6 秒。**

**④ 工具改名 —— 不改名。** `ask_investment_expert` 保留，只改 description。

**⑤ PR #61 排除逻辑 —— 保持不动。** 不在本次范围内放宽。

**⑥ 输出格式 —— 采纳「顶部100字核心结论速览 + 下方四步法深度展开」。**
兼顾手机端扫读与深度：开头先给一段 ≤100 字的结论摘要（涨跌方向+核心原因一句话），紧接着才是完整四步法展开，总篇幅仍是 500~800 字（含这段摘要）。这条已同步进 TECH_DESIGN §4.7 的 `_DEEP_ANALYSIS_GUIDE` 与 TASK_LIST T5 的测试用例。
